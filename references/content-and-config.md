# 内容与配置

先复用用户已给的材料，最多补问影响当前首版的关键信息。保留材料来源与用户判断的区别：外部文章不等于本人观点，工作团队成果不自动等于个人独立完成。

## 最小可用资料

公开称呼、一句方向、一个可展示的作品或一段真实介绍即可起步。联系方式、文章、成长章节均可后补。没有真实材料时运行演示，不为填满布局编造。

## 配置映射

完整字段结构见 [演示配置](../assets/starter/site.config.json)，具体编辑方式见 [站点 README](../assets/starter/README.md)。

| 用户材料 | 配置 |
| --- | --- |
| 公开名、英文署名、标记 | `name`、`nameEn`、`initials` |
| 一句方向、简短介绍、角色 | `tagline`、`intro`、`roles` |
| 个人主线 | `about` |
| 自有肖像与说明 | `portrait`、`portraitAlt` |
| 本人选定公开联系方式 | `email`、`socials` |
| 章节标题、时期、真实正文 | `chapters` |
| 作品标题、为谁、成果、状态 | `projects` |
| 观点/实践文章、分类、小节 | `articles`，`room=orbit/digest` |

双语字段形如 `{ "zh": "真实中文", "en": "Faithful English" }`。翻译保留事实和语气；只有一种语言的材料可以先在两栏填相同内容。元数据以 `defaultLang` 为准，语言按钮只改变阅读偏好；如果用户要求按语言收录，另行实现独立语言 URL 与对应 SEO。

默认 `rooms: []`，不生成 S/O/D/A 或四房间入口，作品与文章照常展示。只有使用者明确需要独立档案时才添加对应项，不要求四项齐全；显示名自定，字母可留空。显式禁用某档案会隐藏其路由及关联文章。此功能不是访问控制；真正私密材料不能进入源码、静态资源或客户端配置。文章 `slug` 使用稳定英文标识。

项目没有公开地址时 `url` 留空。项目截图必须脱敏且有权使用。`/images/` 仅支持本地栅格图片，禁止数据 URL、第三方追踪图片与未经审核的 SVG。邮件和链接只从明确字段生成，不执行用户输入的 HTML。

## 从演示到个人内容

所有演示段落都标有「示例 / Sample」，没有假收入、客户数量或评价。生成真实站点时逐条替换或删除；没有作品就让 `projects` 为空，没有文章就让 `articles` 为空。核对完成才把 `demo` 设为 `false`。不要仅去掉示例标记却继续冒用样例经历。

网站只是公开信息的载体。不要把完整简历、私人复盘、密钥、未公开客户资料或原始聊天记录直接填入配置。
